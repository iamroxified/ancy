# ANCYN Membership Management

Laravel 13 application with an Inertia React/TypeScript public site and protected membership administration for the Alliance of North Central Youth of Nigeria.

## Requirements

- PHP 8.3 or later with the extensions required by Laravel and PDO SQLite or PDO MySQL
- Composer
- Node.js 22 or later and npm
- SQLite for local development, or MySQL 8+ for production

## Local Setup

```sh
composer install
cp .env.example .env
mkdir -p database
touch database/database.sqlite
php artisan key:generate
php artisan migrate
php artisan db:seed
npm install
npm run build
php artisan serve
```

Set `APP_URL` to the local application URL in `.env`. The sample environment uses SQLite at `database/database.sqlite`; configure MySQL before running migrations if you prefer a server database. Do not copy production credentials into `.env.example` or commit `.env`.

For a local development server with asset watching and scheduled tasks, use the commands provided by the project scripts or run the Laravel and Vite processes separately. The production frontend is generated by `npm run build`.

## First Administrator

There is no public administrator registration page and `db:seed` does not create an account. Create the first Super Admin from a trusted terminal after migrations:

```sh
php artisan ancy:make-admin admin@example.org "ANCYN Super Admin" --role=super_admin
```

The command asks for a password twice using hidden terminal input. Use a unique password with at least 12 characters, mixed case, numbers, and symbols. The password is never printed. Do not pass passwords as command-line arguments. Records Administrators can be created with `--role=records_admin`.

## Main Routes

- `/`, `/about`, `/coverage`, `/register`, `/contact`, and `/privacy` are public.
- `/admin/login` is the administrator login.
- `/admin` lists and manages members, live reports, and filtered CSV export.
- `/admin/messages` is the protected contact inbox.
- `/admin/settings` is restricted to Super Admins and edits public content, contact/social details, privacy text, and retention periods.
- `/dashboard` is an authenticated alias for the admin dashboard.

Records Administrators can manage membership and contact messages. Only Super Admins can change public site settings. Admin actions such as viewing records, edits, status changes, exports, message views, and settings updates are written to `audit_logs`; logs do not include full VIN or phone values.

## Registration and Location Data

VIN and phone values are encrypted with Laravel's application key. Keyed hashes support duplicate checks and exact-value search without plaintext lookup columns. Member lists mask both values. CSV exports omit VIN and phone. State/LGA/ward/polling-unit choices are validated against the normalized location catalog on the server. The catalog is loaded from the supplied `states-and-lgas-and-wards-and-polling-units.json` dataset.

The seven covered administrative areas are selected from the supplied dataset during seeding. Eighteen exact duplicate polling-unit labels within a ward are represented once by the database's natural-key constraint. Verify the dataset against current official sources before production use. Do not claim INEC verification.

## Retention and Backups

Super Admin settings control member and contact-message retention periods in days. A value of `0` disables automatic deletion; this is the default. When either period is positive, Laravel's daily scheduler runs `ancy:purge-expired-data`, which deletes records older than their configured period and stores aggregate deletion counts in the audit log.

Run the scheduler locally with:

```sh
php artisan schedule:work
```

In production, configure the platform scheduler to run `php artisan schedule:run` every minute. Retention deletion is permanent; review the legal basis and chosen periods before enabling it.

Back up the database using your database provider's encrypted backup mechanism and store copies outside the web root with restricted access. Back up `APP_KEY` separately in a secret manager: loss or rotation of the key without a planned re-encryption process makes existing encrypted VIN and phone values unreadable. Test restoration regularly. No voter-card images or uploaded member documents are stored by this application.

## Production Deployment

1. Configure production environment variables and a least-privilege database account. Set `APP_ENV=production`, `APP_DEBUG=false`, `APP_URL`, database connection values, a secure session driver/cookie configuration, and mail/logging settings as appropriate.
2. Install PHP dependencies with `composer install --no-dev --optimize-autoloader`.
3. Install JavaScript dependencies and run `npm run build` in the release build environment.
4. Run `php artisan migrate --force` as a controlled deployment step, then `php artisan db:seed --force` to import the ANCYN State/LGA/Ward/Polling Unit catalog. The seeder is idempotent and creates no administrator account.
5. Create or rotate administrators using `php artisan ancy:make-admin` from a trusted terminal.
6. Point the web server document root at `public/`; enable HTTPS and ensure `storage/` and `bootstrap/cache/` are writable by the application user but not publicly browsable.
7. Run `php artisan config:cache`, `php artisan route:cache`, and `php artisan view:cache` after environment configuration.
8. Configure the Laravel scheduler and an encrypted, tested database backup process.

Keep `.env`, database backups, logs, and encryption keys out of source control and public storage. Confirm organizational contact details and social links in Super Admin settings before publishing them.

## Verification

```sh
php artisan test
npm run types:check
npm run build
DB_CONNECTION=sqlite DB_DATABASE=:memory: php artisan migrate:fresh --force
```

The test suite uses Laravel's test database configuration. The in-memory migration command validates the migration chain without modifying the configured local database.
